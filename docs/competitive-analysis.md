# OralVerse-CAD — Competitive Analysis

## Reference Products

### Invisalign ClinCheck (Align Technology)

The market leader in clear aligner treatment planning. ClinCheck is a cloud-based platform used by orthodontists and general dentists to review, modify, and approve treatment plans generated by Align's proprietary AI.

**Core workflow:**
1. Doctor takes intraoral scans with iTero scanner (proprietary)
2. Scans uploaded to Align cloud overnight processing
3. Treatment team at Align manually reviews and generates initial plan
4. Doctor receives ClinCheck plan in 7–14 days
5. Doctor modifies in ClinCheck Pro, approves, submits to manufacturing

**What makes it clinically superior:**
- Root visualization extrapolated from crown geometry (patented algorithm)
- Gingival margin detection and recession prediction
- Per-tooth occlusal contact display at every stage
- Clinician-set target position by dragging teeth in 3D
- Smart staging: algorithm groups teeth with interdependencies
- Attachment shape library with placement optimization
- IPR scheduler with enamel thickness safety limits
- Clinician modification history with rollback
- Refinement case management

**What it does poorly:**
- Closed ecosystem (requires iTero scanner)
- Black-box AI — clinicians cannot understand why the plan looks the way it does
- 7–14 day turnaround (not real-time)
- High cost per case ($1,300–$1,800 wholesale per arch)
- No CBCT integration (bone envelope is ignored)

---

### uLab Systems

uLab is the most direct competitor to what OralVerse-CAD is attempting. It is a software-only platform (not tied to a scanner) and is known for giving orthodontists the most control over treatment planning.

**Core workflow:**
1. Import STL files from any scanner
2. AI auto-segments teeth and detects landmarks
3. Orthodontist manually adjusts targets in 3D
4. Submit to any lab or print in-house

**What makes it clinically strong:**
- Scanner-agnostic (any STL input)
- Real-time local computation (no cloud processing delay)
- Full 3D tooth manipulation with collision detection
- Point-based tooth editing (move crown tip, root tip independently)
- Bolton analysis built in
- Archform selection library (oval, tapered, square, custom)
- Per-contact-point IPR measurement
- Export to any manufacturer

**What it does poorly:**
- Learning curve is steep (many degrees of freedom)
- No AI treatment suggestion (full manual planning)
- No root prediction without CBCT

---

### 3Shape Ortho Analyzer

3Shape's orthodontic analysis module within the broader Dental System software. Primarily used as a diagnostic tool rather than a treatment planning tool.

**Strengths:**
- Model superimposition (overlay scans from different appointments)
- Cephalometric analysis (from 2D X-rays or CBCT)
- Bolton analysis with tooth size calculator
- Tooth movement simulation (basic, not aligner-stage-based)
- DICOM integration
- Extensive report generation

**Weaknesses:**
- Treatment planning is secondary — this is a diagnostic platform
- No aligner stage generation
- No attachment optimization
- Integration with treatment planning requires external software

---

### LingOral (LingOral Digital Orthodontics)

A platform for lingual (inside surface) bracket and aligner treatment. Less relevant architecturally but relevant as an example of a platform that handles difficult geometry (lingual surfaces are harder to visualize and plan).

**Relevant features:**
- Multi-angle viewer with synchronized occlusal + lateral + frontal views
- Bracket prescription import
- Archwire prescription
- 3D printed indirect bonding tray design

## OralVerse Strengths

1. **Open architecture.** No scanner lock-in. Any STL from any intraoral scanner can be imported.

2. **ML adapter interfaces.** `ml_adapters.py` defines clean protocol interfaces for plugging in different models. The system is designed to be model-agnostic before any model exists.

3. **Frontend abstraction quality.** The `ToothObject` / `SegmentationResult` interface cleanly separates geometry from metadata. The Zustand stores (despite duplication) correctly separate concerns. The staged planner API (`{initial, target} per tooth`) is a correct abstraction.

4. **Clinical measurement infrastructure.** `clinicalMeasurements.ts` is well-structured with a documented coordinate system and confidence reporting. Upgrading from centroid-based to landmark-based measurements requires only changing the input data, not the structure.

5. **Dataset-driven development.** The `stl_dataset.py` route and `ScanBrowser` UI create a workflow where real patient data (or research datasets) can be loaded immediately, without demo data.

6. **Animation quality.** The `useFrame` lerp/slerp animation with exponential decay produces smooth stage-to-stage transitions that compare favorably to commercial tools.

## Opportunities (Where OralVerse Can Differentiate)

### 1. Explainable AI

ClinCheck's AI is a black box. Orthodontists cannot understand why attachments are placed where they are, or why a particular staging order was chosen. OralVerse can expose the reasoning at every step — which constraint drove stage count, which risk factor triggered an attachment recommendation, why IPR was scheduled at stage 3 rather than stage 1.

### 2. Real-Time Planning

ClinCheck's 7–14 day turnaround is a commercial constraint (manual review team). uLab and OralVerse are both real-time. This is OralVerse's baseline but should be framed as a strong differentiator.

### 3. Open Dataset Integration

3DTeethSeg22 and similar public datasets can be used to train models and evaluate accuracy openly — something Align and uLab cannot do with their proprietary training sets. Publishing benchmark results builds credibility in the research community.

### 4. Direct CBCT Integration

Neither ClinCheck nor uLab integrate CBCT well. A platform that ingests CBCT alongside STL scans and uses the CBCT for bone envelope + root visualization would be genuinely differentiated. This requires DICOM processing (ITK/SimpleITK) and root prediction — see `ml-roadmap.md`.

### 5. Active Learning Loop

Every case treated through OralVerse is a potential training data point. Clinician corrections to AI segmentation are ground truth labels. Building an active learning pipeline around this creates a compounding improvement advantage.

## Minimum Viable Clinical Product

For OralVerse to be usable in a real clinical setting, the following are non-negotiable:

1. Accurate tooth segmentation (≥ 95% correct FDI assignment on typical cases)
2. Clinician-set target positions (not auto-inferred from centroids)
3. Real collision detection (not centroid approximation)
4. Treatment plan export (STL per stage or equivalent)
5. No fabricated clinical feedback (remove the alert() calls claiming to detect collisions)

Items 1–4 map to specific roadmap items in `roadmap.md`. Item 5 is a one-hour fix.
